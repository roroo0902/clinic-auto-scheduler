# 直接在班表鎖定當日班次

管理者開啟「整體班表」或「我的班表」，點選員工的日期，再按「鎖定當日」及「確認鎖定」。已鎖定的日期顯示 🔒；再次點選，按「解除當日鎖定」及確認即可恢復修改。

鎖定包含整天的早、午、晚班及未排班狀態。人工改班必須先解除鎖定；自動排班、智慧建議及發布會檢查鎖定。與指定班別等條件衝突時，應顯示衝突，不能略過鎖定。一般使用者只能查閱。

沿用 `AssignmentLocks`／「排班鎖定設定」九欄，不改月班表內容。每個日期以 A/B/C 三筆保留原班表的存在與不存在班次。操作者與時間由伺服器填入。解除時將該日所有既有鎖定停用，保留其他員工及日期。舊部分鎖定顯示為既有部分班次鎖定，人工修改須先解除。舊複雜編輯入口導向整體班表，伺服器也禁止舊通用表單寫入鎖定。

儲存採管理者重新驗證、ScriptLock、班次與鎖定指紋比對、原子批次寫入及逐欄讀回。結果不明時先重新讀取，不自動重送。直接由 Google Sheets 修改不會取得 ScriptLock，管理者應避免同時在試算表及網站操作同一資料。

部署：先匯出最新完整雲端來源，完成其他聊天合併，再執行 `node scripts/merge-schedule-locks.cjs latest-cloud.gs candidate.gs`。腳本會驗證唯一合併位置、移除舊智慧建議對「鎖定不存在班次」的不正確拒絕，並提高鎖定專用讀取範圍；其他資料表上限不變。來源已含模組時會停止，避免重複合併。不要以舊版 Portal 或 Schedule 覆蓋新雲端來源。

驗證：`node --test`，並使用獨立試算表測試真實寫入、讀回、解除、人工修改與重播拒絕；正式資料不做試寫。發布前還原正式試算表 ID，讀回完整雲端來源比對後，再更新原部署並從正式入口複驗。手機驗證為瀏覽器尺寸模擬，不等同實體裝置測試。
