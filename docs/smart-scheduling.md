# 規則式智慧排班

管理者登入 → 開啟班表 → 智慧排班建議 → 選月份與模式 → 檢查參數並產生建議 → 查看黃色變更格、人力核對及工時 → 勾選確認 → 確認套用。

不使用外部 AI API，沒有模型用量費用。建議只在記憶體產生，不會修改正式班表；通過全部檢查才顯示確認套用。草稿有效 20 分鐘，僅限原登入管理者，參數或班表變更後須重新產生。套用前複製整張「月班表」為「建議前備份_月份_識別碼」，再於同一批次寫入並讀回核對。網路結果不明時不重送，先重新讀取正式班表及備份。

## 必填與來源

- 每日班別人力需求：每天 A/B/C 各一筆最低、最高人數；理想人數空白採最低。休診需明確勾選。人力需求待填表是整理用表，正式引擎不會自動從待填表讀取或覆蓋。
- 日曆設定：每天明確填營業日。政府機關放假日不會自動當成診所休診。
- 班別時間設定：整月有效、同日班別、明確不計工時休息分鐘。現行網站固定 A=4、B=4、C=3 小時；不相符時阻止套用，不能只改建議端工時。
- 員工基本資料：啟用、姓名、任職日期、每日／每週工時上限、每週最多工作日、最多連續出勤天數、最少班間休息時數。其他月／日／週上限及最低班數、最低工時有填就檢查。月目標工時是偏好目標，月工時上限才是硬限制；不會以每月工時標準覆蓋員工個別目標。
- 允許班別組合：明確勾選。員工專屬設定優先於 ALL，沒有明確允許就不安排。
- 月班表：相鄰月份需有已確認班表，以檢查跨月週工時、連續出勤及班間休息。資料不足仍可看暫定建議，但不可套用；不把缺值當成休息。

## 規則範圍

支援最低／理想／最高人數、營業日與班別休診、員工工時與出勤上限、指定日期與每週不可排班、已核准及待審請假、指定班次、整日鎖定（包含鎖定休息）、個人假日、明確允許的整日組合、一般資格人數，以及偏好／晚班／假日／穩定性權重。沒有可排時段紀錄代表未另設限制；不可上班紀錄一律保守遵守。待審請假及「需人工確認」個人假日也暫不排入。

「保留既有班次」只增加班別，不刪原班；「重新建議整月」保留鎖定及指定班次，其他班次可變更。鎖定以整日處理，比單一班次鎖定更保守。

第一版使用逐日、整組班別加入的有限搜尋，先補最低需求，再補理想需求；同時參考月目標工時、出勤天數、偏好及公平性。它不保證最佳解；仍缺人不代表數學上無解。所有最低人數、資格人數及員工最低週工時／班數均再做最終檢查，未通過不開放套用。

員工搭班規則、班別銜接規則、法規政策設定、員工設定歷程、跨月資料完整性表的進階資料解讀，以及資格要求由不同人員擔任，目前尚未支援。這些表出現有效資料時會顯示阻擋原因，不能默默略過。備註中的自然語言不作為可執行規則。這是依表內設定的檢查，不代表已核驗所有法規。

## 部署與驗證

新增 `gas/SuggestionEngine.gs`、`gas/Suggestions.gs` 與 `gas/Suggestions.html`。從較舊 GitHub 版本重新部署時，若 Access.gs 尚無 readSheets_，一併加入 `gas/SuggestionRead.gs`；既有第 25 版以上的雲端已有相同讀取輔助函式，不必重複加入。一般本機建置已含新介面。現有線上介面較新時，使用 `node scripts/merge-suggestions.mjs <剛匯出的雲端原始碼> <輸出檔>` 精確加入新功能，保留其他程式及介面；不要拿舊 Portal.gs 覆蓋正式網站。

執行 `node --test`。測試使用虛構員工，驗證權限、缺值、需求、請假、整日組合、資格、跨月、既有班次、過期草稿、伺服器重新計算、備份、未知寫入結果及不重送。

維持 USER_ACCESSING、原試算表與授權名單，不增加分享權限。Google Sheets 的直接人工編輯無法由 Apps Script 鎖住；套用前再次核對可縮短衝突窗口，但請避免套用同時在 Sheet 編輯班表或參數。
