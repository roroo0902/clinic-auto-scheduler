# 每週可上班時段與特殊日期

管理者從「英靈編成 → 每週可上班時段與特殊日期」進入。選員工與月份後，在星期一至日的早／午／晚班格子勾選可上班時段，預覽修改前後，再確認儲存。手機可橫向滑動週表。上一頁會保留預覽草稿；離開編輯時若有草稿會先顯示捨棄提示。

每次儲存只影響所選員工與月份。特殊日期預設保留，優先於每週模板；可修改或恢復每週設定。未建立模板時不推定可排或不可排；第一次儲存若全部未勾選，預覽會提醒當月皆不可排。可排並不保證排到；正式班表要另行產生及確認。

## Google Sheet

- `每週可上班設定`：月份、員工代碼、姓名、星期（1=星期一至7=星期日）、早／午／晚班可排、更新時間、更新者。一位員工每月完整7列，3個時段欄使用布林勾選。
- `特殊日期可上班設定`：日期、員工代碼、姓名、早／午／晚班可排、更新時間、更新者。每位員工同一天最多一列。

空表只有表頭，沒有預設任何員工的可上班規則。直接編輯 Sheet 時需保持月份／日期為文字、7列完整、勾選欄為布林值；格式錯誤會阻止排班。建議使用網頁，具管理者檢查、預覽令牌、版本比對、自動備份和寫後讀回。

新設定只替換相同員工／日期的舊式 AVAILABLE、UNAVAILABLE、OFF 可排時段。已核准請假、必排班次、排班鎖定、資格與工時上限仍保留。特殊日期取消後恢復每週設定。不同員工與月份不受影響。

## 整合與部署

從最新雲端程式匯出，不可用舊的本機 Portal.gs 覆蓋雲端。首次安裝執行：

```sh
node scripts/merge-weekly-availability.mjs fresh-cloud.gs candidate.gs
node --test
```

合併器把 `WeeklyAvailability.html` 加入既有頁面，把 `WeeklyAvailability.gs` 接在既有服務之後；自動排班、暫定排班、統計與規則建議共用同一份解析結果和快照指紋。原始舊規則保留在 Sheet；套用新設定的日期才以新模板為準。驗收模式保持原有隔離案例。

新增上述兩個工作表及精確表頭後，先在完整隔離副本測試。原生工作表建立及勾選格式請參考 `scripts/weekly-availability-sheet-requests.json`，套用前確認其中工作表 ID 未被使用。正式部署沿用既有部署 ID、USER_ACCESSING 執行身分及原存取權限。部署前後核對正式月班表完全一致。完整部署來源是合併器產生的 candidate.gs；不要在同一 Apps Script 專案重複貼入已合併的模組，也不要執行舊的 build-login-portal 覆寫新雲端介面。
